# Source-backed reminder settings

A proof/card item may use `sourceSettings` to turn a multi-condition instruction into a live
configuration. Its title/note and two to four rows are original lesson content. Stable row IDs
follow `[a-z][a-z0-9-]*` and are unique. Each row has a label, an on/off target, a reason and
specific wrong feedback. At least two actual source-clue groups are required. Do not combine
this mechanism with source recall, source gaps, order, illustrations or calculations in one item.

Every row starts unset. Allow/silence choices immediately change the model, without a correctness
colour until checking. Check evaluates every row separately. A partially correct configuration
keeps its accepted row visible and explains the failed constraint. The exact code-rendered model
changes no operating-system settings and does not establish actual device behavior.

Checked correct settings alone cannot finish the task. The learner must also connect all source
clues and save reasoning. Editing any row clears the configuration check and checked conclusion,
invalidates completion and preserves other rows, source clues and writing. Reload must retain
actual wrong choices; stale completion flags must not override a wrong or unchecked setting.

Check empty, all-on, all-off, reversed, corrected, source-incomplete and edited/reloaded states.
Inspect phone/tablet buttons and feedback. Exercise real Application actions in both native
adapter modes and the offline app. Guided configuration never creates independent attempts,
mastery, listening credit or a lesson pass. Adapter checks are not native GUI validation.

l-ls-course-t05 keeps calls on, including Mum’s calls, while silencing other alerts for the
current exercise. It does not claim only Mum’s number is allowed, a permanent rule, or measured
improvement. Reusing a generated phone-in-another-room picture would not prove this contact
exception; the changing exact configuration is the useful instructional visual.
