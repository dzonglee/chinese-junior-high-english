# Visible source routes

An optional `route: {from, targets: [onTarget, offTarget]}` on a source-settings
row makes its two choices actual destination/next-action labels. Vertical nodes and full-width choices keep English words intact on narrow screens.
The selected target
changes immediately in an arrow model and remains visible when wrong. Each row has
its own labels; legacy rows keep their original shared labels and status badges.

Use short, distinct labels (source ≤32 characters, each target ≤28). Targets must
be trimmed, nonempty strings. A route cannot share a settings model with the silent
pacing diagram. Normal two-to-four-row, source-evidence and own-reasoning requirements
still apply. Every row starts unset; the preview does not select a default answer.

Arrows mean the relationship stated in that task: submission destination or next
action. They do not prove that submission, payment, permission or verification has
already happened. A password-request → ask-a-trusted-adult action must never be
described as sending the password to that adult. Use fictional labels, not real
contact details, passwords, operational URLs or generated “official” documents.

Editing changes the visible target and invalidates checked completion, preserving
other rows, collected clues and learner writing. Storage restoration keeps the
actual chosen destination. Routes remain assisted preparation and create no
independent attempts, mastery, lesson-done or hearing credit. The label content is
translated with the selected spelling variant.

Browser/native drivers check each row's actual labels and changed target, partial
errors, no-source completion guards, edited/reopened repair and full models at three
browser widths. An actual native pass requires inspecting the job and captures;
browser/adapter success alone is insufficient.
