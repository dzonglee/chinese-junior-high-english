# Complete-app UI review · 2026-10-17

APP-UI compares the English app with the maths app at main `933ab32`, using its actual
home, course, practice and profile screenshots plus current source and design instructions.
The maths app was read only. This is a product/interface assessment, not a claim that two
subjects have identical learning outcomes or production readiness.

## Comparison and corrective passes

| Area | Maths reference | English before | English after |
| --- | --- | --- | --- |
| Home | A dominant next lesson and useful daily tasks | Generic hero, scattered numbers and repeated cards | Split lesson cover, actual daily task rows and integrated weekly activity |
| Courses | Compact chapter rows | Configuration fills the first screen | Visible next lesson and real course rows, search and skill chips, optional advanced filters |
| Practice | Distinct study tools and entry patterns | Repeated full-width buttons | Timed-practice feature, six skill tiles, simple setup with optional detailed filters |
| Review | Purposeful review state | Generic empty/card pattern | Empty guidance or real populated mistakes with due status and retries |
| Profile | Compact identity/menu | Nine large cards | Identity, one statistics strip and compact destination rows |
| First use | Focused learner setup | Long form | Three validated steps; exact edition, city and structure preserved |
| Lessons | Interactive work and readable feedback | Earlier teaching integration existed, but visual controls were inconsistent | Cohesive letter tiles, concise step strip, readable feedback and optional long references |

Repeated review also fixed: stale validation toasts; the daily task for a completed studio
reopening that studio; listening preparation opening an unusable audio-only list; duplicate
profile context controls; communication task previews overlapping their action; and native
foreground form preservation. Native tracing then identified a stale failed navigation replacing the new session. The adapter
now ignores stale failures and only uses redirect fallback for a stack-limit error. The focused
actual native builder regression passes; the complete final walkthrough remains pending.
